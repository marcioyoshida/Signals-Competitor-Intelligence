# Roadmap / backlog — 2026-08-16

Living backlog of decided-but-not-yet-built work. Ordered roughly by leverage.
Companion to the phase status in `CLAUDE.md`.

## Source expansion (richer, more sustained narratives)

Current lenses are mostly **structured filings + numbers** (CVM funds/ofertas,
IF.data, Pix, juros, autorizações, SEC 6-K, CVM inf_diário). They carry *what*
happened but little *why it matters*, so narratives read factual-but-thin. The
gap is **qualitative / strategic** signal. Rank candidates by **citation
authority** (the product's moat) × **strategic richness**, and respect the
CLAUDE.md legal rules (government first; public web logged-out + robots.txt;
social/employment only via licensed aggregators — never scrape LinkedIn).

Priority order:

1. **CVM/B3 material facts — SHIPPED 2026-08-16.** `src/ingest/cvm_ipe.py` reads
   the CVM IPE dataset (Fato Relevante / Comunicado ao Mercado), filtered to a
   B3-listed FS watchlist. New `fatos` lens (strategic weight 0.88, high-value
   solo) fused + scored + cited to rad.cvm.gov.br. Verified live: Santander OPA,
   Bradesco/BB/Itaú results disclosures. Schema verified 2026-08-16.
2. **Diário Oficial / CADE / SUSEP / PREVIC — SHIPPED 2026-08-16 as one lens.**
   CADE's and SUSEP's own open-data endpoints are 401/404, but all three publish
   in the DOU — so `src/ingest/dou.py` queries the Imprensa Nacional DOU search
   per watchlisted competitor (quoted phrase), parses the embedded jsonArray, and
   keeps only intel-relevant publishing bodies via a `hierarchyStr` allowlist
   (SUSEP, CADE, BACEN, CVM, CMN, CNSP, PREVIC — drops CARF/tax/sports noise).
   New `dou` lens (strategic weight 0.82). Verified live: SUSEP insurance
   authorizations, CADE antitrust judgments, PREVIC acts → cited narratives.
5. **Trade press — SHIPPED 2026-08-16.** `src/ingest/trade_press.py` consumes
   Google News RSS (a syndication feed) per brand: headline + publisher + link
   only, cite the source, **never scrape article bodies** (paywall/ToS-safe).
   Plus **direct RSS from named outlets** (Valor Econômico, Money Times) for
   fuller coverage + direct publisher links. Full-phrase (accent-folded) title
   match + finance-context filter drop noise (band/stadium; "banco dos réus").
   New `news` lens at a **lower strategic weight (0.55)** — it's
   color, ranks below official filings. Verified live: Nubank US$1bn results,
   Stone fraud incident, analyst views → cited narratives.
6. **Company IR / press pages** — logged-out, robots-respecting; official
   launches/partnerships cited to the source page.
7. **Hiring signals** — only via a licensed aggregator (People Data Labs /
   Explorium); never scraped LinkedIn.

Deprioritized: **X/Twitter** — weak citations for a regulated buyer, noisy, and
the API is now costly; revisit later for *official* competitor accounts only.

These complement (not replace) **real threat scoring** and **emit-on-change**:
strategic events (an M&A filing, a launch) should outscore a routine fund
registration, which is what makes the feed read as prioritized intel.

## Quiet-fintech radar (new-entrant detection)

BCB-regulated fintechs must appear in the "instituições em funcionamento"
registry when authorized — so a **registry diff** catches even quietly-registered
entrants (~24h, no press needed). This is the `new_entrants` lens
(`bcb_autorizacoes` + `detect_new`); it catches the **unknown** entrants a
watchlist can't. Complement: known names → watchlist/aliases (Creditas,
RecargaPay, Neon, InfinitePay/CloudWalk, Nomad — add brand **and** legal names;
Nomad is a blind spot, US-facing, thin BR footprint → needs trade press/IR).

- **Shipped 2026-08-16 — license classification.** `classify_license` maps
  SEGMENTO → compact classes (IP, SCD, SEP, SCFI, microcrédito, banco, …) with an
  `is_fintech` flag; scoring refines the entrant signal by class
  (`ENTRANT_CLASS_WEIGHT`) so a new SCD/IP outranks a new consórcio/cooperativa.
- **Shipped 2026-08-16 — Receita Federal CNPJ (QSA) enrichment.**
  `src/ingest/receita_cnpj.py`: the registry gives an 8-digit CNPJ raiz →
  reconstruct the matriz (raiz + 0001 + DV) → BrasilAPI (public, no key) for
  `nome_fantasia` (brand) + `qsa` (controllers). New entrants now read
  "NDD INSTITUICAO DE PAGAMENTO LTDA (NDD PAY) — Instituição de Pagamento.
  Controlador: NDD HOLDING FINANCEIRA LTDA." Enriches only new entrants (cap
  ONCA_RECEITA_MAX=15), caches by raiz, own wall-clock budget, degrades
  gracefully. Schema verified live (2026-08-16).
- **Shipped 2026-08-16 — link entrants to known parents.**
  `entities.known_parents` resolves an entrant's QSA controllers against the
  known-entity aliases; a new fintech controlled by a known player (e.g. a new
  SCD controlled by NU HOLDINGS → `nubank`) now **clusters into that parent's
  narrative + Entity Watch**, and the entrant reads "… Vinculado a concorrente
  conhecido: Nubank." Self-links excluded. Optional future: corroborate with
  Diário Oficial authorization atos.
- **Limits (honest):** BCB has no clean *pending-application (pleito)* feed, so
  authorization-in-operation is the earliest reliable public catch; daily cadence;
  dormant registrations disambiguated by Pix-participation activity.

## Architecture

- **Entities registry + per-tenant watchlists + CNPJ auto-mapping** — move the
  tracked entities out of the deploy-baked `config/watchlist.yaml` into a DynamoDB
  registry that self-expands from the entrant/Receita pipeline; broad shared
  ingestion + per-tenant read-layer personalization. Design:
  `docs/2026-08-17-adr-entities-registry.md`. Core steps (registry table + seed,
  registry-backed resolution, CNPJ auto-create, alias accumulation) are the
  highest-value slice; per-tenant + UI come with the accounts layer.
  - **Step 1 shipped 2026-08-17** — `onca-entities` table + curated seed (20
    entities) via `entity_registry.seed`.
  - **Step 2 shipped 2026-08-17** — registry-backed `resolve_entities`
    (`_alias_map()` reads the table, caches, falls back to built-in aliases).
  - **Step 3 shipped 2026-08-17** — CNPJ auto-create in the entrant path:
    `entity_registry.auto_create_from_entrant` writes an `ENT#` record
    (`confidence="cnpj"`, brand + legal-name aliases, QSA controllers, CNPJ
    root) for each new fintech entrant, wired after Receita enrichment in
    `lambda_port`. Idempotent by CNPJ; never clobbers a curated id. Verified
    live: forced entrants FINNET + GazinCred auto-created via the deployed
    ingest Lambda, resolvable by CNPJ and name, then cleaned up.
  - Next: step 4 (alias accumulation from all CVM/news signals), then 5–7
    (review queue, per-tenant config, manage-entities UI).

### Structured insight card — 2026-08-22 (the "intelligence, not digest" upgrade)

Highest-leverage *product-perception* change: today a card is a **single
unstructured prose blob** (`SYSTEM`: "Return only the briefing prose — no title,
heading, or markdown"). The target is a **sectioned insight card** that answers
"what does this mean for me?", e.g.:

```
MÉDIO | Bradesco | ALERTA        21-08-2026 17:34 | Threat 0.63 (est.)
Primary Signal   • Restructuring: 324 branches + 2.4k layoffs despite record profit
                   → est. efficiency gain; short-term regional share risk   [Imprensa+CVM+DOU]
Secondary        • Seguros: AI efficiency + weather product (low impact)
                 • Exposure: R$5bi Casas Bahia debt (credit-recovery risk)
Competitive      Network cut larger than recent Itaú/Santander moves; AI cost-cut = sector trend
Recommended      Monitor Q3 cost-to-income + regional branch density
```

What already renders: **header** (tier · entity · ALERTA · timestamp · score "·
est.") — done. What's missing are four capabilities, **none of them ingestion**
(this is a synthesis/output + dashboard change):

11. **Structured, insight-bearing card.** Sub-capabilities, by build order:
    - **A — Structured card schema (core lift, doable now).** Replace the single
      `narrative` string with `{primary:{event, implication, sources}, secondary:[
      {event, impact}], competitive_context, recommended_actions:[]}`. Touches the
      synth prompt (emit structured JSON, not prose), output parsing + **per-section
      citation guards** (the existing `citations.py` enforcement must run per field,
      not once), the dashboard card render (sectioned), and a **legacy-prose
      fallback** so old narratives still render. The fusion engine already clusters
      multi-lens signals per entity — this adds *ranking within the cluster* (top =
      primary by strategic weight/recency, rest = secondary) + the schema.
    - **B — Implication / "so-what" inference.** The `→ est. efficiency gain;
      regional share risk` line. Interpretive, so **labeled as estimate/inference**
      (reuse the silence/longitudinal derived-axis discipline; extend the existing
      "do not invent numbers" guard). This is what makes it read as intelligence.
    - **C — Competitive context.** "Larger/smaller than peer moves; aligns with
      sector trend." The **data enabler is already shipped** — `feature_store.cohorts`
      (per-industry peer baselines) — this is the **comparative/peer-cohort axis**
      (ADR-003 Wave 1) surfaced as a card field, not a separate narrative.
    - **D — Recommended actions.** LLM monitoring suggestions, kept metric-oriented
      and **labeled as a suggestion** (lowest-confidence content; keep generic —
      "monitor Q3 cost-to-income", not directive advice).

    **Guardrail (non-negotiable):** B/C/D layer *interpretation over facts*, which is
    the ADR-003 inference/defamation surface for a regulated buyer. Build them
    **grounded + explicitly labeled** (est./inferência badges, every claim traceable
    to a cited primary/secondary signal), never asserted as fact. A/B are shippable
    without new ingestion; C needs the comparative axis wired to the card; D last.

## Commercial packaging & multi-tenancy — see [ADR 002](2026-08-18-adr-commercial-multitenancy.md)

Subscribers buy **industry modules** (add-ons); concentrated/high-gross
industries (banking, investment banking) price premium, fragmented ones (fintech)
entry. Pricing is **measured, not guessed** — set from per-industry data volume +
player concentration once instrumented. Core invariants:

- **Broad shared ingest, entitlement enforced server-side.** Client-side module
  filtering is obfuscation; the client must never receive non-entitled data (and
  neither may derived aggregates — KPIs, entity lists, search).
- **The registry is never shipped.** Tenants get only a derived projection
  (slug/label/timeline/score), via a resolve-not-enumerate, rate-limited path —
  never a query/scan of the table, never DynamoDB creds.
- **Identity gates modules.** Cognito/accounts (ADR 001 step 7) is a prerequisite
  for paid modules (step 6) — the numbered order flips.
- **Vendor vs tenant ownership.** Registry, pipeline, raw/digests, synthesis, and
  entitlement logic stay in the **vendor account** (the moat). Tenant side is at
  most a thin consumption stack against the vendor API, or a bring-your-own-bucket
  sink for the tenant's *scoped* feed — never the registry or pipeline.

**Phase plan:** A) IP hardening (S3 policies/logging/lifecycle; account BPA;
registry-as-source-of-truth) — *partially shipped (S3 posture); remainder paused*.
B) industry taxonomy + per-industry measurement — **shipped 2026-08-19** (taxonomy,
concentration + volume/coverage measurement, industry review queue). C) identity
(Cognito). D) entitlement read boundary (tenant `modules[]` + scoped feed
API/shards). E) packaging/pricing/billing + Marketplace. F) manage-entities UI.
A–B are safe pre-tenant; C gates D–E.

## Shipped 2026-08-17
- **Fixed run-date vs data-date conflation (dashboard "stuck since 08-13").**
  Narratives were keyed in S3 by `as_of` = the *source data date*, which is
  pinned to CVM Informe Diário. That date lags (weekend/publish delay) and had
  been stuck at 2026-08-13 — so every day's run overwrote the same
  `narratives/2026-08-13/` folder: no new date partition appeared, entity
  timelines collapsed to one point, and (latent) once wall-clock passed 08-27
  the 14-day `load_recent_narratives` window would drop 08-13 and blank the feed
  while the pipeline still reported success. Fix: narratives now carry a
  **`run_date`** (BRT calendar day the signal was surfaced) separate from
  **`as_of`** (source data age). `run_date` partitions S3 and drives the feed
  window / timeline / sort; `as_of` stays the "dados de" display. See
  `synthesize.run_date_today`, `digest_io.write_narrative`,
  `feed_builder.build_feed` (`data_date` + top-level `run_date`). Verified live:
  first new `narratives/2026-08-17/` folder since 08-13; feed `dates` extends to
  today while `as_of` correctly still reads 2026-08-13. (Collapsed 08-14..08-16
  history is unrecoverable — the fix is forward-looking.)

- **Intraday triggers (3/day, extensible to 5)** — Shipped 2026-08-18. Replaced
  the single ~daily EventBridge rule with three UTC crons aligned to Brazilian
  gov publish windows and corporate office hours (08–18 BRT): **Abertura 06:45**
  (`cron(45 9 * * ? *)`, DOU AM edition + overnight CVM/SEC), **MeioDia 12:30**
  (`cron(30 15 …)`, morning BCB acts + AM news), **Fechamento 17:30**
  (`cron(30 20 …)`, afternoon filings + SEC US-morning). Brazil is UTC-3 with no
  DST, so UTC crons never drift. Grow 3→5 by adding tuples to `pipeline_runs`
  in `infra/app.py`. Safe/cheap: diff-engine dedup + emit-on-change mean extra
  runs only surface genuinely-new signals; the only cost that scales with
  frequency is the nova-lite synth pass (single-digit $/mo). Per-**source**
  triggering was analysed and rejected — it needs a per-lens digest-merge layer
  and doesn't lower cost (ingest is near-free; cost tracks synth runs, not
  ingest triggers). Narratives now also carry **`run_at`** (BRT wall-clock of the
  run that last changed them); the feed card renders it as a time suffix
  (`18-08 · 12:30`) so users can tell which intraday pass surfaced a signal. See
  `synthesize.run_at_now`, `feed_builder` (`run_at` passthrough), `index.html`
  (`fmtTime`).

- **ADR 003 Wave 1 — Silence axis (first user-facing detector).** New
  `src/synth/silence.py`: a deterministic nominator (no LLM) that inverts
  emit-on-change — it narrates the **absence** of an expected signal. Gate:
  an entity with an established cadence (`active_days ≥ 3`) that has been quiet
  past `max(7d, 2.5·mean_gap, mean_gap+3)`; escalation `silence_tier` (1/2/3) with
  a cooldown so a standing silence re-fires only when it worsens. Cards are
  **labeled inference** (`axis:"silence"`, `is_inference`, `mode:"derived"`,
  no citations — silence has no source URL by nature; Decision 4) and capped at
  0.6 threat (a watch, never a top alert). **Feedback-loop guard:** silence cards
  are written to `narratives/` like any other, so the feature store now excludes
  derived axes from "activity" (`is_activity_narrative`) — else emitting "X went
  quiet" would reset X's `days_since_last`; the detector recomputes freshness from
  activity narratives only, immune to the pre-synth snapshot lag. New `OncaSilence`

- **ADR 003 Wave 1 — Longitudinal axis (second detector).** New
  `src/synth/longitudinal.py` (`OncaLongitudinal` Lambda): narrates a **trajectory
  break** — an entity whose latest activity sits anomalously far from its own
  threat baseline (`score_z`), in either direction — *escalation* (z≥+2, reports
  the real elevated level) or *cooling* (z≤−2, a low 0.35-capped watch). Differs
  from silence in three ways: (1) **lag-free** — recomputes features fresh from

  run later; (2) **grounded** — cites the *driving* narrative (its citations +

  overlaps silence (absence, `≥ 7`). Same guards as silence: derived axis excluded
  from feature-store activity (`DERIVED_AXES += longitudinal`), break-tuned

- **[ADR 003 — Narrative dimensions](2026-08-19-adr-narrative-dimensions.md)**
  authored (Proposed). Today every narrative is keyed (entity|signal, run_date) —
  a single-run cross-sectional fusion; cross-time structure exists only downstream
  (the dashboard sparkline). ADR 003 generalizes the narrative to
  **(subject_type, subject_key, axis)** and adds four axes beyond cross-sectional:
  **longitudinal** (pattern-break vs. an entity's own baseline), **threaded**
  (an incident updated in place), **behavioral** (campaign/event cadence), and
  **relational** (dyadic edges — merger likelihood, legal dispute). Two structural
  shifts: identity beyond run_date (+ `emit-on-update` + thread/edge lifecycle),
  and a **derived-state layer** (per-entity feature store → incident/thread store →
  relationship graph) feeding a multi-producer synthesizer. Key risks recorded:
  relational inference is a **defamation surface** (review-gated, labeled as
  inference, never asserted as fact), and new threads/edges reuse the false-nexus
  precision discipline (confidence gate + review queue). **Operative (person)
  layer** (Shift 3): add `person` nodes + typed, time-bounded role edges (QSA
  controllers, CVM directors, DOU/court parties — fields already ingested),
  turning the feed into projections over a heterogeneous **{entity, person,
  incident}** intelligence graph; unlocks operative-profile, talent-movement,
  interlock, beneficial-ownership ("who's behind the shell"), and revolving-door
  narratives — and people often *ground* otherwise-speculative entity edges as
  sourced facts. Hardest guardrail: **LGPD/PII** (public professional roles only,
  public figure vs. private individual, no CPF key). An axis is framed as a point
  in a **four-knob design space** (subject · temporal stance · polarity ·
  baseline); the full set adds **comparative/peer-cohort, cohort/vintage,
  counterfactual/silence, thematic/sector-current, regulatory-lifecycle/deadline,
  ecosystem/dependency, predictive/leading-indicator** to the original six, each
  **classified by effort/challenge/risk/enabler/value** (sweet spot = silence +
  thematic + regulatory-deadline: high value, low risk, medium effort). **Waved
  sequencing:** Wave 0 build the shared per-entity **feature store** (unlocks 4
  axes) → Wave 1 comparative/longitudinal/silence/cohort + thematic/deadline →
  Wave 2 threaded/behavioral → Wave 3 relational → operatives (beachhead first);
  predictive is time-gated, ecosystem source-gated. Independent of Phase C.
