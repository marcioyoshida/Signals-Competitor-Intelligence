## 2. Decisions that differ from Tarantula

- **D1. Provisioned users only.** Onça tenants are provisioned, never created by a sign-in (#179). `principal_of(sub)` reads the live Cognito record (tenant attribute plus groups) and the tenant's licensed modules. No modules and no elevated group means the sign-in ends on an error page and no code is issued. Entitlement is **re-read on every refresh**; a de-provisioned user's family is revoked.
- **D2. Three audience-bound resources, one scope each** (`/mcp`→`onca:read`, `/mcp/ops`→`onca:write`, `/a2a`→`onca:read`). A token for one is refused at the others (tested live). `onca:write` is issued only to members of the `operator` or `admin` Cognito group, and is re-checked on refresh.
- **D3. Per-request entitlement.** The resource server recomputes the caller's licensed modules from the tenant record on every call and scopes the feed with the same `scope_feed_to_modules` as `/api/feed`. The token only names who is calling.
- **D4. Reuse, don't fork, the write and ask paths.** `ask`, A2A and `/mcp/ops` invoke the existing agent and act Lambdas with the claims event API Gateway would produce, so the Phase D read boundary, elevated-only writes, idempotency (keys are per caller) and journaling are the ones already tested.
- **D5. Pure-Python verification.** The shared Lambda bundle has no crypto library. KMS signs (a non-exportable P-256 key); `src/dashboard/ecdsa_p256.py` verifies and converts DER signatures, cross-checked against `cryptography` in `tests/test_ecdsa_p256.py`.
- **D6. No edge gate above any of this.** These paths go through the Cognito HTTP API with **no** JWT authorizer, and each Lambda answers 401 + `WWW-Authenticate` itself (the "unreachable handshake" trap). CloudFront behaviors were consolidated (`/mcp*`, `/.well-known/*`, `/*.txt`) to stay under the distribution's 25-behavior quota; the site holds no other `.txt` (test-enforced).
- **D7. Client registration:** CIMD first (unchanged), plus **pre-registered confidential clients** for platforms that can't use it. Copilot Studio's "Manual" OAuth and Gemini Enterprise's A2A registration both take a client id + secret, may omit PKCE and `resource`. Such a client stores only the secret's SHA-256, must authenticate at `/token` (post or Basic), and carries a `default_resource`. Public clients still require PKCE S256. There is still no DCR (deprecated in the spec; owner decision, fleet-wide) — so Copilot Studio's "Dynamic discovery" option is not available, by design.
- **D8. Kill switch:** SSM `/onca/oauth/disabled=true` refuses every flow and every bearer token; metadata keeps answering.

## 3. Registry data defect found while building

The alias index `ALIAS#ITAU` points at the real-estate fund `icdi11` ("ITAÚ ICDI11"), because that fund carries a bare manager-name alias `ITAU`. `lookup_entity` now ranks an exact display-name match above alias-index hits. The data itself needs a curation fix — tracked separately; not edited here.

## 4. Operations

- Register a platform client: `scripts/oauth_register_client.py` (secret written once to a mode-600 file, only the hash stored; `--revoke` deletes it).
- End-to-end check: `AWS_PROFILE=my2027 .venv/bin/python scripts/oauth_mcp_e2e.py`.
- Regenerate discovery files after changing `discovery.py`: `scripts/build_discovery.py`.

## 6. Open owner decisions

1. **AWS Marketplace (#185) contradicts ADR 015/016 as written.** They define the Marketplace SKU as **Sovereign** — an in-account stack, telemetry off — and explicitly dropped "Marketplace as an orthogonal billing rail" over the shared Portal. An "AI agents & tools" SaaS listing whose product surface is the shared `/mcp` endpoint is exactly that dropped rail. Options:
   - **Owner decision 2026-09-28: (a).**
   - **(a) Keep ADR 015/016.** The Marketplace listing stays the Sovereign in-account product (a CloudFormation/AMI delivery plus the resolve API). #185 becomes "list the Sovereign product in the AI agents category", and the remote MCP is not its surface.
   - **(b) Amend ADR 015.** Allow a SaaS listing for the shared MCP/API: Marketplace subscription → SNS → `OncaTenantConfig` provisioning, billed by Marketplace metering, **replacing** Stripe for those buyers (never both — one invoice per buyer).

   **Recommendation: (b), scoped to the Agentic API/MCP only.** Procurement through the AWS bill is the reason #185 exists, and the dashboard stays direct-billed. It is a revision of a recorded ADR, so it's the owner's call.

   **Hard blocker either way:** AWS Marketplace seller registration needs the legal entity (Smart Signals LLC formation pending), tax and bank details.
2. **Directory submissions (#183)** go out under the owner's GitHub/Anthropic/Postman identities, one at a time, with the owner's go-ahead (same rule as Tarantula #106–#110).
3. **Legal pages** adapt Tarantula's owner-approved texts to what Onça stores (Portuguese first, English below). They should be reviewed before the first directory submission.
4. **Verified-host badge allowlist** (consent page) ships empty, as in Tarantula.
